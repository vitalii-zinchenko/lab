# Performance Tests

Load and stress tests for the Gin server, written with [k6](https://k6.io/) in TypeScript.

## Prerequisites

**1. Install k6:**
```bash
# macOS
brew install k6

# Linux
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg \
  --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" \
  | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update && sudo apt-get install k6
```

**2. Install Node dependencies** (only needed once):
```bash
make perf-install
# or:  cd perf/k6 && npm install
```

**3. Start the server:**
```bash
make server-up              # Docker
# or:  go run ./cmd/server  (from server/golang/)
```

## Test tiers

| Script | VUs | Duration | Purpose |
|--------|-----|----------|---------|
| `smoke.ts` | 1 | 1 min | Sanity-check every endpoint works end-to-end |
| `load.ts` | 0 → 50 | ~4 min | Simulate realistic concurrent traffic with per-endpoint SLOs |
| `stress.ts` | 0 → 200 | ~6 min | Find the breaking point under extreme concurrency |

---

## Running tests

```bash
# From the project root (Makefile bundles TS → JS then runs k6)
make perf-smoke
make perf-load
make perf-stress

# Point at a different host/port
BASE_URL=http://staging:8080 make perf-load

# Run directly from perf/k6/ (skips Makefile)
cd perf/k6
npx webpack && k6 run dist/smoke.js
BASE_URL=http://staging:8080 npx webpack && k6 run dist/load.js
```

## What each test does

### smoke.ts
Single VU walks through the full CRUD lifecycle every iteration:

1. `GET /health` — checks status and body
2. `POST /items` — creates a new item, captures the returned `id`
3. `GET /items/{id}` — verifies the item exists and fields are correct
4. `GET /items` and `GET /items?limit=5` — verifies list endpoint + limit cap
5. `DELETE /items/{id}` — deletes the item
6. `GET /items/{id}` again — asserts **404**

### load.ts
50 concurrent VUs run the same lifecycle but with realistic think-time (0.5 – 2 s).
Per-endpoint latency thresholds are enforced:

| Endpoint | p(95) target |
|----------|-------------|
| `GET /health` | < 50 ms |
| `GET /items` | < 200 ms |
| `POST /items` | < 300 ms |
| `GET /items/{id}` | < 100 ms |
| `DELETE /items/{id}` | < 100 ms |

### stress.ts
Ramps to 200 VUs with minimal think-time to find where the server degrades.
Thresholds are relaxed (< 5% errors, p(95) < 2 s) — the goal is observation,
not strict SLOs. Watch the k6 terminal output for the inflection point.
